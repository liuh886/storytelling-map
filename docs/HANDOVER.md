# 会讲故事的地图 — Handover

> 交接对象：本地 Agent
> 交接日期：2026-11-25
> 项目状态：第一幕原型已完成四轮迭代，当前为真实地形版；第二幕已定方向、未开工。用户决定后续由本地 Agent 跟进，本文档为唯一交接依据。

## 一句话定义

会讲故事的地图，是一个把文本 / 故事中的地理要素抽取出来、转成一张可交互的近 3D 地图，并让地图本身按幕、按场讲故事的产品。

它不是静态插图，不是几张配图拼贴，也不是可以自由飞行的游戏地图。故事在地图上演，地图就是舞台。

## 起源

想法来自用户大量观看 YouTube 历史讲述视频的体验：讲述者讲明清皇帝与重臣的故事时，听者脑中会自然浮现一张地图。产品要做的，就是把那张脑内地图显性化、交互化，让地形、城池、路线和人物位置本身承担叙事。

第一个故事已经选定：建州女真 / 努尔哈赤崛起，到清军入关，整条线对照明朝的衰落来讲。

## 产品原则

接手后不要改动以下原则，它们是用户逐条定下来的：

- **按幕 / 按场组织。** 一个故事拆成若干幕，每幕再拆成若干场。镜头、版图、人物都随场次推进。
- **时间非匀速。** 时间流速由戏剧性决定，不按年份平均分配。平淡年份可以一笔带过，关键战役要放慢、拆步细讲。第一幕中萨尔浒一战独占全幕一半以上的时长，就是这一原则的样板。
- **景别有语义。** 共五档：全景、远景、中景、近景、特写。全景讲疆域与大势，中 / 远景讲城池攻防与军队运动，近景讲阵形与兵种，特写讲细节。切换景别就是切换叙事尺度。
- **每场先介绍主人公。** 进入一场之前，先出主人公介绍卡，观众点「进入战场」后才进入地图场面。
- **主线走镜头，支线只放标记。** 主线人物和事件获得镜头；其他关键人物只在地图上以标记存在，显示他们当时在哪、在干什么，不抢主镜头。详见支线人物层一节。
- **地形必须是真实地形。** 这是用户最后、也是最硬的一条纠正，见技术现状与已否决项。

## 叙事架构总览

| 幕 | 时间范围 | 主线 | 结尾（用户拍板） |
|---|---|---|---|
| 第一幕 | 1583—1627 | 努尔哈赤崛起 | 1627 年崇祯登基 |
| 第二幕 | 1627—1636 | 崇祯与袁崇焕 | 1636 年 4 月皇太极改国号大清 |
| 后续幕 | 1636—1644 | 尚未细定 | 方向至清军入山海关 |

分幕边界是用户在语音讨论中逐条改定的，过程中出现过两个易错点，接手时务必守住：

- 皇太极建立大清（1636）**不属于第一幕**。用户最初提过在崇祯上台处接建清，讨论后明确否决：第一幕只到崇祯上台为止，建清放到第二幕结尾。
- 锦州失守是 1642 年松锦之战之后的事，晚于建清，不要把顺序倒置。第二幕也不以锦州为节点。

## 第一幕：赫图阿拉到萨尔浒（已建成）

第一幕共六场，讲完努尔哈赤的崛起：

1. 十三副甲起兵
2. 古勒山之战，统一女真
3. 1616 年建后金，联科尔沁
4. 1618 年「七大恨」告天，攻抚顺
5. 1619 年萨尔浒之战
6. 尾声

关键设计点：

- **萨尔浒分六步。** 四路明军分路推进、被后金各个击破的过程逐步呈现，不是一帧打完。每步有步进说明，攻守之势条同步翻转。
- **版图分 0—5 共六个阶段**随场次生长，与叙事严格对应，不要改成连续动画糊过去。
- **尾声是一条连锁反应链**，不是新战役：1619 年辽东主力丧失与辽饷加派、1620 年万历去世与泰昌一月、党争激化，一路推到 1627 年崇祯即位，最后一帧停在崇祯登基。
- 1635 年改称满洲、1636 年建大清的内容**已从第一幕完全删除**，不要加回。

## 第二幕：崇祯与袁崇焕（已定方向，未开工）

第二幕尚未构建，以下是已定稿的框架，开工时直接按此执行，不要重新讨论分幕：

- **起点：** 1627 年崇祯上台，与第一幕尾声无缝衔接。
- **主线：** 崇祯与袁崇焕的故事，集中在 1628—1630 年这不到三年。弧线为：1628 年崇祯授袁崇焕尚方宝剑、许「五年复辽」；袁回宁远经营关宁防线；1629 年皇太极绕道入关，袁回师北京城下退敌；1630 年 9 月袁崇焕被崇祯处死。情绪落点是「赢了仗，却输给了朝廷」——地图上防线还在，人没了。
- **皇太极作为终点张力。** 皇太极在第二幕中有几次出色行动，是本幕的对面主角：1627 年征朝鲜稳住后方、1629 年冬绕过宁远—锦州防线直抵北京城下、借反间计使崇祯自毁袁崇焕。叙事上把他处理为终点式人物：他的成功在结尾兑现。
- **袁崇焕死后直接快进。** 1630—1636 年间具体事件不多，用户已同意一笔带过，只保留几个节点：大凌河之战、旅顺失陷、察哈尔归附、1635 年改称满洲。
- **结尾：** 1636 年 4 月，皇太极在沈阳改国号为大清，版图颜色与国号在同一帧一起变，第二幕收在此处。

第二幕的场次拆分、景别分配、萨尔浒式的分步战役（己巳之变是否拆步）尚未细定，是开工时第一件要和用户确认的事。

## 支线人物层：15 人（已定版）

支线人物层是与主线并行的一层。做法：人物以标记放在地图上，位置与一两句状态随场次推进而变化；尚未出生的人物在对应场次隐藏；图层可开关；点击标记弹出信息卡。不给支线人物主镜头。

定版名单共 15 人，不要增删，除非用户另行指示：

- 后金 / 清一方：努尔哈赤、皇太极、多尔衮、范文程、顺治
- 明朝皇室：万历、魏忠贤、崇祯
- 明朝将领：熊廷弼、袁崇焕、毛文龙、洪承畴、吴三桂
- 农民军：李自成、张献忠

使用效果举例（第一幕）：李自成还在陕西，张献忠在湖广，毛文龙在皮岛，吴三桂还是宁远的年轻将领，崇祯还是信王。观众应一眼看出主线之外还有另一盘棋在同时下。第二幕沿用同一层，人物位置与状态按 1627—1636 年更新即可。

### 迭代史（四代，不要退回前三代）

| 代 | 渲染方式 | 被否决 / 升级原因 |
|---|---|---|
| 1 | 2D SVG + CSS 透视倾斜模拟 3D | 用户指出没有用 Three.js，「近 3D」措辞与实现不符 |
| 2 | Three.js 程序化地形 | 用户评价沙盘太简陋：纯色、无纹理、光影平 |
| 3 | Three.js + 文明系列风格化 | 地貌分区、图标化城池军队、约 600 棵松树、低多边形平直着色；用户仍不认可 |
| 4（当前） | Three.js + 真实 DEM + OpenStreetMap 底图 | 用户明确要求以 OpenDEM / OpenStreetMap 这类真实数据做中国地图 |

第 3 代的文明式可读风格（地貌分区一眼可辨、城池与军队图标化、信息层级分明）是用户认可的方向，第 4 代换底座时保留了这一思路，可继续沿用。

### 当前实现要点（第 4 代）

- **地形：** SRTM 实测高程数据（Terrain Tiles / 与 OpenDEM 同源），构建时取回高程瓦片烘焙为 `assets/dem.png` 高程网格，Three.js 按真实高程起伏（适度夸张）。
- **范围：** 东经 118.6°—128.4°，北纬 39.2°—44.4°，覆盖辽东全域至长白山、辽东湾、鸭绿江一带。
- **底图：** 同一范围的 OpenStreetMap 瓦片拼图 `assets/basemap.jpg`，铺在 3D 地形上，也用作 SVG 回退层的底图。页脚与图例已标注数据来源：SRTM DEM 与 © OpenStreetMap contributors，保留不要删。
- **全部要素按真实经纬度落位：** 13 座城池（赫图阿拉在新宾、宁远在兴城海岸、宽甸在鸭绿江边等）、五条真实水系（浑河、辽河、苏子河、鸭绿江、太子河）、六阶段版图、1619 年四路进军与反击路线（西路为沈阳 → 抚顺 → 萨尔浒的真实东向路线）、8 支军队、15 位支线人物。
- **高程抽查已验证：** 沈阳 54 米、抚顺 82 米、赫图阿拉 279 米、萨尔浒 173 米、长白山主峰区 2236 米、宁远 12 米，均与真实值吻合。
- **叙事数据模型与渲染层解耦：** 源码中叙事状态集中在 `CHAPTERS`（六场）、`SARHU_STEPS`（萨尔浒六步）、`PEOPLE`（15 人）三组数据，3D 与 SVG 回退共用同一套叙事状态与地图接口。后续换渲染、扩幕次都应复用这组数据，不要重写文案。
- **回退：** DEM 加载失败时自动回退程序化地形；WebGL 不可用时自动回退 SVG 沙盘并给出提示。回退只是保险，不能当作主路径交付。
- **交互：** 五档景别为真实相机机位平滑移动；支持有限角度拖拽环绕与滚轮缩放；军队按叙事时序登场（第一场不显示，第二场起淡入，萨尔浒全数列阵），这是设计而非缺陷。

## 用户已明确否决或纠正的事项

- **程序化假地形不可接受。** 无论风格化做得多精致，地形形状、河道、城池位置对不上真实辽东就是不合格。新故事、新幕次同样适用：先找真实 DEM 与底图，再做风格化。
- **不要用「近 3D」这类措辞掩盖实现差距。** 说是 Three.js 就必须是 WebGL 真 3D，能环绕、能俯仰、有视差。
- **沙盘质感曾被评价为「太简陋」。** 触发点包括：纯色几何体、无树无纹理、光影平。真实地形版解决了底座真实性，但质感是否达标未经用户确认，不要自认为已解决。
- **第一幕不写建清，第二幕不以锦州失守为节点**，见叙事架构一节。
- **叙事文案与已定内容视为定稿。** 历轮升级都只换渲染层，不动六场文案、萨尔浒六步、版图阶段与人物状态文案。本地 Agent 继续沿用这一纪律：改视觉可以，改故事要先经用户确认。

## 给本地 Agent 的下一步

按顺序推进：

1. **先请用户上手验真实地形版。** 重点四项：萨尔浒、赫图阿拉、辽河的位置是否正确；拖拽环绕；滚轮缩放；点人物标记。拿到反馈再动代码。
2. **根据反馈二选一：** 若位置与交互通过但质感仍不满意，继续在真实 DEM 底座上做质感升级（纹理、植被、城池与军队模型、光影），不要再换底座；若底座有错位，先修坐标映射。
3. **再开第二幕。** 先与用户定场次拆分与己巳之变的分步方案，复用第一幕的数据模型与组件（主人公介绍卡、景别、非匀速时间轴、版图生长、支线人物层），地理范围沿用当前 DEM 覆盖，北京方向如需出图再评估扩图。
4. **后续幕次**按同一模式推进至 1644 年入关，锦州 / 松锦之战（1641—1642）与山海关（1644）届时再细定，不要提前写进前两幕。
